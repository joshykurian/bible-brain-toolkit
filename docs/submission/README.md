# Submitting to the plugin directories

This folder helps you list the toolkit in the three big directories where site owners look for extensions.

| Directory | For | Guide | Review time (typical, not guaranteed) |
|---|---|---|---|
| WordPress.org Plugin Directory | the WordPress plugin | [wordpress-org.md](wordpress-org.md) | days to weeks, with a human review |
| Drupal.org | the Drupal module | [drupal-org.md](drupal-org.md) | days for a project page; a security review is a separate, optional step |
| Joomla Extensions Directory (JED) | the Joomla plugin | [joomla-jed.md](joomla-jed.md) | days to weeks |

## Decide one thing first: who is the publisher?

All three directories protect the **Bible Brain** and **Faith Comes By Hearing** names. Two honest paths exist:

1. **Official path.** The listing is published from an official Faith Comes By Hearing account, under the name "Bible Brain Players". This is the strongest path for trust and for use of the brand. It needs agreement from the people who manage the Bible Brain brand and a shared team account that survives staff changes.
2. **Independent path.** The listing is published from a personal or other organization's account, with a name that does not start with the brand and says it is not endorsed, for example "Audio Bible Players for Bible Brain". The packaging script builds this version for you.

Choose the path before you create accounts, because the plugin name and its web address (slug) are hard to change later.

## What is ready, and what is not

Ready in this repository:

* A packaging script for the WordPress.org version: `scripts/make_wporg_package.py`.
* A directory-format `readme.txt` with the required "External services" and privacy sections.
* Listing artwork (original icon and banners) generated by the script.
* Copy-paste descriptions and reviewer notes in each guide.
* GPL licence tags on the PHP files and a Joomla update-server template.

Still yours to do (nobody can do these for you):

* Create the accounts and, for WordPress.org, turn on two-factor authentication.
* Download the official hls.js file for the WordPress build (this workspace had no internet access).
* Test the plugin in a real WordPress, Drupal and Joomla site, with debugging turned on. The toolkit's tests run its own code and proxy, but not the three CMS platforms.
* Replace the sample screenshots with screenshots of your own site.
* Confirm that the Bible Brain terms allow the way you distribute the plugin (see the terms link in each guide) and keep your own contact address ready for reviewers.

## After a listing goes live

* Answer support questions in the directory forum or issue queue. Reviewers and users judge a listing by how it is maintained.
* Release fixes quickly and keep the version numbers in step (`python scripts/check_versions.py`).
* Record each release in `CHANGELOG.md` and the directory changelog.
